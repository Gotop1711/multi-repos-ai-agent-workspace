# rea / terms

- **Blank-style labels in the prototype.** `REA_PROTO@3fdf47c tests/mock/api/rulesSpecificSetting.json` writes `_` where a number the inputs supply would go: code 303's option 06 is `每_週限制次數` (`:5367`) and four of its five sub-block titles read `_日_月_年內限申報次數`, `_日_月_年內至多執行_次，且間隔_日_月_年`, `同部位限申報_次，且限定時間_日_月_年內，不得再次申報`; the dialog renders the sentence from prefix/suffix text around the inputs, never the title. A `_` in a prototype label is template copy, not a defect.
- **The kernel's definition is primary.** Where `REA_kernel` and `REA_PROTO` define the same thing differently — a field's values, its type, its constraints, its vocabulary — the kernel's meaning is the product's and the editor follows it; the prototype governs form (layout, the sentence, the order things read in), not meaning. Ruled by the owner on 2026-09-16, generalising the 類別 case below. It settles **conflicts, not absences**: a field the prototype has and the kernel does not is still a request to the kernel, never a UI-side invention — and the kernel may decline it: 205/206 專任 (`EmploymentType`) was dropped at `REA_kernel@de35a2f` and the owner dropped its request and the prototype's lock on it (2026-10-19); the ui follows (`REA_UI@3ad7356`). Already decided this way: 304's `visitType` keeps the kernel's three 就診類別 where the prototype offers two, and its mode 11 counts stay the kernel's `Number` where the prototype types them `text` (rule-codes).
- **類別 vocabulary.** The kernel's `01 代碼 / 02 開頭 / 03 開頭範圍 / 04 群組` is the product's: one order shared by 105, 302, 305 and 307 (`REA_kernel@2ff26b0 Codes/V1.0/_105.cs:239`, `_302.cs:299`, `_305.cs:29-32`, `_307.cs:306`) and what the deployment serves.
