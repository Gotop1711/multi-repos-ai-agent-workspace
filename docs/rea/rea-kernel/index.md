- **The leaf's `Name` is the group name, and where it goes.** On `develop` since `f49ea00` (merged 2026-09-17; the feature branch's own `876cd3d` is content-identical but not an ancestor): `StructureValidator` requires a leaf's `Name` non-blank — "應帶前端的群組名稱" — and unique among the leaves of one `Code` (`Validation/StructureValidator.cs:29-35`, `:70-73`). The whole `Logic` tree is serialized to one JSON string in the `rule_sets` document (`Context/ClaimValidatorDbContext.cs:13-18,34-40`), so `Name` persists verbatim; and at save time `RuleSetSL` runs the translator and stores its output in `TranslatedRules` (`Implementation/V1/RuleSetSL.cs:119-129`), where the name is baked into every engine `RuleName` as a suffix — `Rule_<code>_<name>`, `Rule_<code>_Skip_<name>`, `Rule_<code>_Main_<name>`, children suffixed recursively — and into `Properties["Name"]` (`Translator/V1.0/RuleSetTranslator.cs:58-115`). `RuleNode` has **no `GroupName`** (`POCO/V1/Rules/RuleSet.cs:69-117`) and the API never sets `JsonUnmappedMemberHandling.Disallow` (`API/NHI.API.ClaimValidator/Program.cs:9-12`), so a `GroupName` key is discarded in silence and reaches neither store.
